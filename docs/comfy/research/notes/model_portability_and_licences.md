# Portability of PhotoCraft's model set away from ComfyUI (as of 2026-10-16)

Scope: Qwen-Image-Edit-2511, Krea 2 Turbo, Qwen-Image-2.1, Qwen-Image-Layered, SAM 3 / 3.1, Qwen3-VL 4B, plus the Lightning and Multiple-Angles LoRAs. Every claim carries a source; where a primary page was gated (HTTP 401) or missing (404) that is recorded under Gaps rather than guessed. Byte sizes come from the Hugging Face Hub API (`/api/models/...?blobs=true`) and are exact at the time of the query.

## Key question 1: Does non-ComfyUI code implement Qwen-Image-Edit-2511 (multi-reference) and Krea 2 Turbo? Which classes, since when?

### Takeaway
Yes for both. Hugging Face diffusers has `QwenImageEditPlusPipeline` (multi-image, shipped in v0.36.0, Dec 2025; the 2511 card instructs loading that class from `Qwen/Qwen-Image-Edit-2511`) and `Krea2Pipeline` / `Krea2Transformer2DModel` (documented against diffusers v0.41.0, released 2026-10-06, with a `from_single_file` loader for Krea's own `turbo.safetensors`). Krea also ships its own standalone `inference.py` and an SGLang path. The reference implementations are all PyTorch; no Rust port of either DiT was found.

### Cited Findings
- The official 2511 model card loads the model with `QwenImageEditPlusPipeline.from_pretrained("Qwen/Qwen-Image-Edit-2511", ...)`, installs diffusers from the GitHub dev branch, and passes `"image": [image1, image2]` with `true_cfg_scale=4.0`, 40 steps. The card lists 20B parameters, BF16 safetensors, Apache 2.0, and says 2511 "integrates selected popular LoRAs directly into the base model" so "generating new viewpoints can now be done directly with the base model" — [Qwen/Qwen-Image-Edit-2511 model card](https://huggingface.co/Qwen/Qwen-Image-Edit-2511)
- Hub API: `Qwen/Qwen-Image-Edit-2511` createdAt 2025-12-17, licence tag apache-2.0, safetensors total 20,430,401,088 parameters — [HF API](https://huggingface.co/api/models/Qwen/Qwen-Image-Edit-2511?blobs=true)
- diffusers v0.36.0 release notes list "QwenImage Edit Plus" as a new pipeline that "is capable of taking multiple input images as references" — [diffusers 0.36.0 release summary](https://releases.sh/release/rel_OHA3BZv5YFYfyO3e9eTZD); a third-party checkpoint's `model_index.json` records `_diffusers_version: 0.36.0.dev0` with class `QwenImageEditPlusPipeline` — [FireRed-Image-Edit model_index.json](https://huggingface.co/devsquad8338/FireRed-Image-Edit-1.0/blob/main/model_index.json)
- diffusers Qwen-Image docs table: `QwenImageEditPlusPipeline` accepts `image=[img1, img2]`, documented against `Qwen/Qwen-Image-Edit-2509`; all Qwen-Image pipelines use `FlowMatchEulerDiscreteScheduler` and the Qwen2.5-VL-7B-Instruct text encoder; `guidance_scale` is ignored (reserved for guidance-distilled models) and CFG is driven by `true_cfg_scale` plus a negative prompt — [diffusers Qwen-Image docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/qwenimage)

- Krea 2 Turbo card: released 2026-06-22 as "Krea 2 v1.0"; Turbo is "a post-trained checkpoint with additional fine-tuning and distillation" of Krea-2-Raw; 12B stated (Hub metadata says 13B); official code `github.com/krea-ai/krea-2` (`inference.py`, `turbo.safetensors`, `--mu 1.15`, 8 steps, CFG 0); diffusers `Krea2Pipeline` "requires installing diffusers from source"; SGLang supported — [krea/Krea-2-Turbo model card](https://huggingface.co/krea/Krea-2-Turbo)
- diffusers Krea 2 docs (links resolve to `v0.41.0` source): `Krea2Pipeline(scheduler: FlowMatchEulerDiscreteScheduler, vae: AutoencoderKLQwenImage, text_encoder: Qwen3VLModel, tokenizer, transformer: Krea2Transformer2DModel, text_encoder_select_layers, is_distilled, patch_size=2)`; `Krea2Transformer2DModel.from_single_file("https://huggingface.co/krea/Krea-2-Turbo/blob/main/turbo.safetensors")` is supported; Turbo recipe `num_inference_steps=8, guidance_scale=0.0`; Base recipe 28 steps, `guidance_scale=4.5`; also a Modular Diffusers variant (`Krea2TurboAutoBlocks`, guidance-free) — [diffusers Krea 2 docs](https://huggingface.co/docs/diffusers/en/api/pipelines/krea2)
- diffusers v0.41.0 was released 2026-10-06 and added Qwen-Image 2.1 (`QwenImage21Pipeline`) — [diffusers release summary](https://releasebot.io/updates/huggingface/diffusers); `Qwen/Qwen-Image-2.1` card: `from diffusers import QwenImage21Pipeline` — [Qwen/Qwen-Image-2.1 card](https://huggingface.co/Qwen/Qwen-Image-2.1)
- Qwen-Image-Layered: `QwenImageLayeredPipeline.from_pretrained("Qwen/Qwen-Image-Layered")`, needs transformers>=4.51.3 and diffusers from main; params `layers` (default 4), `resolution` (640 recommended, 1024 available), `cfg_normalize`, `true_cfg_scale=4.0`, 50 steps — [QwenLM/Qwen-Image-Layered README](https://github.com/QwenLM/Qwen-Image-Layered); [diffusers docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/qwenimage)

- Apple-only: Krea 2 Turbo has MLX ports via mflux (q4/q8) — [MLXBits/krea-2-mlx-q4](https://huggingface.co/MLXBits/krea-2-mlx-q4)

### Inferences
- The diffusers Edit-Plus pipeline and ComfyUI's `TextEncodeQwenImageEditPlus` implement the same conditioning contract (384² VL image, 1024² latent reference, "Picture N" prefixes, 64-token drop, last hidden layer), so a native port can be validated against either.
- "2511 integrates selected popular LoRAs" means the Multiple-Angles capability no longer needs the fal/dx8152 LoRA on 2511; keeping the LoRA path only matters for 2509.

### Gaps
- No primary diffusers release note pinned the exact PR that added `QwenImageEditPlusPipeline`; the v0.36.0 release summary is a secondary mirror of the GitHub release.
- The 2511-specific "index_timestep_zero" reference method (see Q2) is in ComfyUI; whether diffusers' Edit-Plus pipeline applies the same for 2511 was not verified from the source read.

## Key question 2: What exactly must a native runtime reimplement (architecture, tokenization, VAE, Edit-Plus conditioning, reference-latent method, sampling recipe)?

### Takeaway
Qwen-Image family: a 60-block dual-stream MMDiT (hidden 3072, 24 heads × 128, 3-axis RoPE [16,56,56]), a Qwen2.5-VL-7B text/vision encoder whose last hidden state (3584-d) is fed through RMSNorm+Linear, a Wan2.1-style 16-channel f8 VAE, references appended as extra image tokens with RoPE axis-0 index 1,2,…; rectified-flow sampling with a rational time shift (ComfyUI's `ModelSamplingAuraFlow`, shift 3.1 in the official 2511 template), Euler, "simple" schedule, true-CFG 4 at 40 steps, plus CFGNorm. Krea 2: a 28-layer single-stream MMDiT (hidden 6144, GQA 48/12, SwiGLU, RoPE [32,48,48]) conditioned on 12 tapped Qwen3-VL-4B layers (12×2560 = 30720 features/token), same Qwen-Image VAE, mu=1.15 fixed shift, 8 steps, no CFG. Qwen-Image-2.1 changes everything: 7B single-stream DiT, Qwen3-VL-8B encoder, 64-channel 16× VAE.

### Cited Findings
**Qwen-Image / Edit-2511 transformer (ComfyUI `comfy/ldm/qwen_image/model.py`, Apache-2.0 code adapted from QwenLM)**
- Defaults: `num_layers=60`, `num_attention_heads=24`, `attention_head_dim=128` (inner dim 3072), `patch_size=2`, `in_channels=64` (16 latent ch × 2×2), `out_channels=16`, `joint_attention_dim=3584` (text in → RMSNorm `txt_norm` → `txt_in` Linear to 3072); `pooled_projection_dim=768` accepted but unused — [ComfyUI model.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/ldm/qwen_image/model.py)
- Blocks are dual-stream: separate image/text branches with their own adaLN modulation (6×dim), LayerNorm, GELU-tanh FeedForward; joint attention concatenates `[txt, img]` after separate QKV projections with RMSNorm on Q/K. No single-stream blocks. `EmbedND(dim=128, theta=10000, axes_dim=[16, 56, 56])`; axis 0 is index/time, axes 1–2 are H/W; text ids start at `txt_start`. Timestep: `Timesteps(256, scale=1000)` → `TimestepEmbedding` → 3072; no guidance embedding — same source
- Reference latents: each ref is patchified and appended to the image tokens with its ids appended to `img_ids`; the output keeps only the first `num_embeds` tokens. Default method `"index"`: target index 0, first reference index 1, second 2, … on RoPE axis 0, no spatial offset (`index += 1; h_offset = 0; w_offset = 0` then `img_ids[:, :, :, 0] += index`). Other methods: `"negative_index"` (−1, −2, …), `"index_timestep_zero"` (same indexing but timestep doubled with zeros for reference tokens, `timestep_zero_index` marks the boundary), and anything else = spatial tiling at index 1 — same source
- Conditioning node `TextEncodeQwenImageEditPlus`: up to 3 images; each scaled to 384×384 total pixels for the VL encoder and to 1024×1024 total pixels (sides rounded to multiples of 8) for `vae.encode`; prefix `"Picture {i}: <|vision_start|><|image_pad|><|vision_end|>"` per image; wrapped in a `llama_template` whose system text starts "Describe the key features of the input image (color, shape, size, texture, objects, background)" and ends `<|im_start|>user\n{}<|im_end|>\n<|im_start|>assistant\n`; reference latents attached via `conditioning_set_values(..., {"reference_latents": ref_latents}, append=True)` — [ComfyUI nodes_qwen.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy_extras/nodes_qwen.py)
- Text encoder wrapper (`comfy/text_encoders/qwen_image.py`): model `Qwen25_7BVLI`, `layer="last"`, `layer_norm_hidden_state=False`, `embedding_size=3584`; template prefix is removed dynamically by locating the second `<|im_start|>` (token 151644) and skipping `user` (872) + `\n` (198) rather than a hard-coded 64; image placeholder token 151655 is replaced in order with image entries — [ComfyUI qwen_image.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/text_encoders/qwen_image.py)
- `Qwen25_7BVLI_Config`: hidden 3584, intermediate 18944, 28 layers, 28 heads, 4 KV heads, head dim 128, rope theta 1e6, mrope `rope_dims=[16,24,24]`; vision tower `Qwen2VLVisionTransformer(hidden_size=1280, output_hidden_size=3584)` — [ComfyUI llama.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/text_encoders/llama.py); the HF Qwen2.5-VL-7B-Instruct has 8,292,166,656 parameters, Apache-2.0, created 2025-01-26 — [HF API](https://huggingface.co/api/models/Qwen/Qwen2.5-VL-7B-Instruct)
- Latent format `Wan21`: `latent_channels=16`, `latent_dimensions=3`, `scale_factor=1.0`, per-channel `latents_mean`/`latents_std` (16 values) applied in `process_in/out` — [ComfyUI latent_formats.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/latent_formats.py); diffusers describes the VAE as "The Qwen-Image variational auto-encoder (f8, 16 latent channels)" (`AutoencoderKLQwenImage`) — [diffusers Krea 2 docs](https://huggingface.co/docs/diffusers/en/api/pipelines/krea2)
- `supported_models.QwenImage`: `sampling_settings = {"multiplier": 1.0, "shift": 1.15}`, `latent_format = Wan21`, inference dtypes bf16/fp32, clip target Qwen2.5-7B (prefix `qwen25_7b.transformer.`), `memory_usage_factor 1.8` — [ComfyUI supported_models.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/supported_models.py)

**Sampling recipe**
- `time_snr_shift(alpha, t) = alpha*t / (1 + (alpha-1)*t)` (identity at alpha=1); `ModelSamplingDiscreteFlow.sigma(timestep) = time_snr_shift(shift, timestep/multiplier)`; sigma table built from `arange(1..1000)/1000`; flow-matching (`CONST`) `calculate_denoised = model_input - model_output*sigma`, `noise_scaling = sigma*noise + (1-sigma)*latent` — [ComfyUI model_sampling.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/model_sampling.py)
- Official Comfy template "Image Edit (Qwen-Image 2511)": `ModelSamplingAuraFlow shift=3.1`, KSampler `euler` / `simple`, 40 steps CFG 4 without LoRA, 4 steps CFG 1 with the Lightning LoRA, `CFGNorm strength=1`, files `qwen_image_edit_2511_fp8mixed.safetensors`, `qwen_2.5_vl_7b_fp8_scaled.safetensors` (CLIPLoader type `qwen_image`), `qwen_image_vae.safetensors`, LoRA `Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors`; reference method chosen via `FluxKontextMultiReferenceLatentMethod` — [Comfy workflow_templates image_qwen_image_edit_2511.json](https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/templates/image_qwen_image_edit_2511.json). PhotoCraft's own `crates/genai/workflows/qwen-edit-2511-*.json` use the same `shift: 3.1`, `CFGNorm strength 1.0`, `euler`/`simple` (local repo grep).
- `ModelSamplingAuraFlow` node default shift is 1.73 (the 3.1 is a template override) — [docs.comfy.org ModelSamplingAuraFlow](https://docs.comfy.org/built-in-nodes/ModelSamplingAuraFlow.md)
- CFGNorm (post-CFG, default): `scale = (‖cond‖ / (‖cfg_out‖ + 1e-8)).clamp(0, 1); return cfg_out * scale * strength` — attenuate-only; a `pre_cfg` variant rescales before CFG ("Matches the norm-scaled CFG used by models like Lens") — [ComfyUI nodes_cfg.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy_extras/nodes_cfg.py). diffusers Edit-Plus does the equivalent inside the pipeline: `neg + scale*(pos - neg)` then rescaled to the conditional prediction's norm — [diffusers source](https://raw.githubusercontent.com/huggingface/diffusers/main/src/diffusers/pipelines/qwenimage/pipeline_qwenimage_edit_plus.py)
- diffusers' default shift for Edit-Plus is resolution-dependent: `calculate_shift(base_seq_len=256, max_seq_len=4096, base_shift=0.5, max_shift=1.15)`, linear in image_seq_len, sigmas `linspace(1, 1/steps, steps)` — same source. For Lightning LoRAs, diffusers' example sets `use_dynamic_shifting=True, time_shift_type="exponential", base_shift=max_shift=log(3)` ("shift=3 used in distillation"), `base_image_seq_len 256`, `max_image_seq_len 8192`, `true_cfg_scale=1.0`, 8 steps — [diffusers Qwen-Image docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/qwenimage)

**Krea 2**
- Flow-matching single-stream MMDiT with grouped-query attention; text conditioning taps hidden states from twelve Qwen3-VL decoder layers per token, fused inside the transformer by a text-fusion stage; decoded with the Qwen-Image VAE; scheduler expects `use_dynamic_shifting=True, base_shift=0.5, max_shift=1.15, base_image_seq_len=256, max_image_seq_len=6400`; distilled checkpoint uses fixed `mu=1.15`; CFG convention `cond + g*(cond-uncond)` (enabled when g>0, equals standard CFG with scale 1+g); `max_sequence_length=512` fixed, padded/truncated; RoPE: text tokens at origin, image tokens at `(0,h,w)`; `prompt_embeds` shape `(B, text_seq_len, num_text_layers, text_hidden_dim)` — [diffusers Krea 2 docs](https://huggingface.co/docs/diffusers/en/api/pipelines/krea2)
- ComfyUI `krea2.py`: `KREA2_TAP_LAYERS = [2, 5, 8, 11, 14, 17, 20, 23, 26, 29, 32, 35]`, `hidden_states[k]` with no offset, permuted to `(B, seq, 12, 2560)` and flattened to 30720 features/token for the DiT's `txtfusion` adapter; same ChatML template as Qwen-Image; `thinking=True` drops Qwen3-VL's empty `<think>` block; prefix dropped by the same second-`<|im_start|>` rule — [ComfyUI krea2.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/text_encoders/krea2.py)
- `Qwen3VL_4BConfig`: hidden 2560, intermediate 9728, 36 layers, 32 heads, 8 KV heads, head dim 128, rope theta 5e6, mrope `[24,20,20]`, interleaved MRoPE, tied embeddings — [ComfyUI llama.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/text_encoders/llama.py)
- Community MLX conversion describes the DiT as 28-layer single-stream, hidden 6144, GQA 48 query / 12 KV heads, head_dim 128, SwiGLU, 3-axis Flux-style RoPE [32,48,48], per-head QK-norm, sigmoid-gated attention, AdaLN-single — [MLXBits/krea-2-mlx-q4](https://huggingface.co/MLXBits/krea-2-mlx-q4) (secondary; consistent with the 12B figure)
- `supported_models.Krea2`: `shift 1.15`, `latent_format Wan21`, dtypes bf16/fp16/fp32, clip prefix `qwen3vl_4b.transformer.`, `memory_usage_factor 2.2` — [ComfyUI supported_models.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/supported_models.py)

**Qwen-Image-2.1**
- "7B parameters in its visual generation component (32 Single-Stream DiT layers)"; examples at 2048×2048 — [Qwen/Qwen-Image-2.1 card](https://huggingface.co/Qwen/Qwen-Image-2.1)
- ComfyUI `QwenImage21`: `shift 0.69` ("scheduler mu at 1024x1024, base 0.5 at 256 tokens, max 0.9 at 8192 tokens"), latent format `QwenImage21` with `latent_channels=64`, `spacial_downscale_ratio=16`, 2-D latents, per-channel mean/std; text encoder Qwen3-VL 8B (`qwen3vl_8b.transformer.`), `memory_usage_factor 6.0` — [supported_models.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/supported_models.py); [latent_formats.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/latent_formats.py)

**Qwen-Image-Layered**
- Fine-tune of Qwen/Qwen-Image (~20B, BF16); architecture "VLD-MMDiT (Variable Layers Decomposition MMDiT)" plus an "RGBA-VAE that unifies the latent representations of RGB and RGBA images"; trained from PSD-derived multilayer data — [arXiv 2512.15603](https://arxiv.org/abs/2512.15603); [Qwen/Qwen-Image-Layered card](https://huggingface.co/Qwen/Qwen-Image-Layered). **SAM 3 / 3.1**
- SAM 3: 848M parameters; a DETR-based detector conditioned on text, geometry and image exemplars plus a tracker inheriting SAM 2's encoder-decoder, sharing one vision encoder; a "presence token" improves discrimination between related prompts — [facebookresearch/sam3 README](https://github.com/facebookresearch/sam3)

- A SAM 3.1 checkpoint mirror states it hosts "only the SAM 3.1 model checkpoints, with no Transformers integration" — [research21/sam3.1 commit](https://huggingface.co/research21/sam3.1/commit/bab7fac3d08db9d6a9d07a7b4ddee29a358fbf28) (unofficial namespace)

### Inferences
- For PhotoCraft's image-only use (click/text/subject selection) SAM 3.1's changes are irrelevant: the release notes describe tracker-side changes only, so SAM 3 image-detector ports (transformers, ONNX exports) should apply unchanged to 3.1 weights — unverified against the 3.1 state dict.
- The "shift 3.1" constant is a ComfyUI template value feeding `time_snr_shift`; diffusers reaches a comparable schedule via `calculate_shift` (mu) with an exponential time shift. A native port must pick one and match it numerically; the two are not identical formulas.
- Krea 2's 30720-wide text conditioning means a native runtime cannot reuse a generic "last hidden state" text-encoder API; it must expose all hidden states of Qwen3-VL-4B (as llama.cpp's embedding API does not by default — see Q5).

### Gaps
- Krea 2 DiT hyper-parameters (28 layers, 6144 hidden, GQA 48/12, RoPE [32,48,48]) come from a community MLX card, not from Krea or diffusers config text; verify against `krea/Krea-2-Turbo/transformer/config.json`.
- Qwen-Image-Layered's RGBA-VAE channel layout and how layers are laid out in the latent sequence were not in the abstract or model card; the paper body (HTML/PDF) was not read.
- ComfyUI's `supported_models.QwenImage` default shift is 1.15 while the official template overrides to 3.1; no primary source explains the 3.1 choice.

## Key question 3: Are ComfyUI's fp8_scaled / fp8mixed / nvfp4 safetensors repacks a documented, portable format?

### Takeaway
They are standard safetensors containers, but the quantization layout is ComfyUI's own: per-layer `comfy_quant` JSON-bytes tensors naming a `QUANT_ALGOS` format, with `weight_scale` (+ `weight_scale_2`, `input_scale`, `pre_quant_scale` for NVFP4, uint8-packed E2M1 in 16-element blocks) and kernels from Comfy-Org's Apache-2.0 `comfy-kitchen`. Nothing found documents compatibility with NVIDIA ModelOpt/TensorRT-LLM NVFP4 checkpoints or diffusers' loaders; diffusers instead loads the official bf16 shards or Krea's single-file bf16. The format is readable from Rust (plain safetensors + a few conventions) but dequantization/kernels must be reimplemented.

### Cited Findings
- `comfy/quant_ops.py` registers `QUANT_ALGOS`: `float8_e4m3fn` (storage float8_e4m3fn; params `weight_scale`, `input_scale`; `TensorCoreFP8E4M3Layout`), `float8_e5m2`, `nvfp4` (storage uint8; `weight_scale`, `weight_scale_2`, `input_scale`, `pre_quant_scale`; `TensorCoreNVFP4Layout`; `group_size 16`, `pad_16x`), `mxfp8` (`group_size 32`), `int8_tensorwise`, `convrot_w4a4`, `asym_w4a8_int8`, `w6a8_int8`. FP8 scale cast to float32; a scale of `"recalculate"` is `amax(|w|)/fp8max`. NVFP4 per-block scales come from `ck.quantize_nvfp4` (`comfy_kitchen`); import failure logs "fp8 and fp4 support will not be available"; CUDA backend disabled below CUDA 13 — [ComfyUI quant_ops.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/quant_ops.py)
- `comfy/ops.py`: per-layer format stored as `sd[f"{prefix}comfy_quant"] = torch.tensor(list(json.dumps(quant_conf).encode("utf-8")), dtype=torch.uint8)`, read back with `json.loads(layer_conf.numpy().tobytes())`; FP8 scale read from `weight_scale`; `MixedPrecisionOp` decides per module whether to use a quantized matmul; dequantization via `QuantizedTensor.dequantize()`; a legacy `fp8_linear` path ("Legacy FP8 linear function for backward compatibility") uses unit scales and clamps inputs to ±448. The current file has no `scale_weight`/`scaled_fp8` handling — [ComfyUI ops.py](https://raw.githubusercontent.com/Comfy-Org/ComfyUI/master/comfy/ops.py)
- Comfy's quantization guide (mirror): quantized checkpoints are "standard safetensors files with quantized weight tensors, associated scaling parameters, and a `_quantization_metadata` JSON entry"; layers listed in a config are quantized and "all others load in bfloat16 by default"; "sensitive operations like final projections should be kept in higher precision" — [Mintlify mirror of ComfyUI quantization docs](https://www.mintlify.com/Comfy-Org/ComfyUI/advanced/quantization); the official `docs.comfy.org/advanced/quantization` URL returned 404 at query time
- comfy-kitchen: "Fast kernel library for Diffusion inference with multiple compute backends", Apache-2.0; FP8 E4M3 per-tensor (SM ≥ 8.9), NVFP4 E2M1 16-element blocks (SM ≥ 10.0), MXFP8 E4M3 32-element blocks with E8M0 scales (SM ≥ 10.0); backends eager/cuda/triton (+hip, ascend); CUDA wheels need CUDA runtime ≥ 13.0 and driver r580+, Python ≥ 3.10, torch ≥ 2.7; optional `[cublas]` extra for NVFP4 on Blackwell; no statement on ModelOpt/TensorRT-LLM compatibility — [Comfy-Org/comfy-kitchen](https://github.com/Comfy-Org/comfy-kitchen)
- Third-party converter `convert_to_quant` produces FP8/INT8/NVFP4/MXFP8 for ComfyUI; NVFP4/MXFP8 need Python 3.12+, PyTorch 2.10+, CUDA 13.0+, comfy-kitchen — [silveroxides/convert_to_quant](https://github.com/silveroxides/convert_to_quant)
- Loader pitfalls reported: do not set `weight_dtype` to fp8_e4m3fn when the file is already fp8_scaled; an NVFP4 file missing `_quantization_metadata` "loads unquantised, crashes later" — [localaimaster guide](https://localaimaster.com/blog/comfyui-quantization-format-errors) (secondary)
- "fp8mixed": no primary definition found; community descriptions say mixed = "keeping important layers in bf16" — [search summary, Comfy quantization guide mirror](https://gitcode.com/GitHub_Trending/co/ComfyUI/blob/master/QUANTIZATION.md)
- Nunchaku/SVDQuant alternative: the only 2511 Nunchaku builds found are third-party (`QuantFunc/Nunchaku-Qwen-Image-EDIT-2511`, "independent re-quantization ... not affiliated with ... MIT HAN Lab or the Nunchaku project", Apache-2.0, diffusers example) — [QuantFunc card](https://huggingface.co/QuantFunc/Nunchaku-Qwen-Image-EDIT-2511); community NVFP4 for ComfyUI (`ANXS1/Qwen-Image-Edit-2511-NVFP4`, "rough calibration", RTX 5090 832×1280 4 steps ≈3.45 s total) — [ANXS1 card](https://huggingface.co/ANXS1/Qwen-Image-Edit-2511-NVFP4); official Nunchaku Qwen-Image (not Edit-2511) ships INT4 (pre-Blackwell) and NVFP4 (50-series) at rank 32/128 with a diffusers example — [search result, nunchaku-tech/nunchaku-qwen-image]

### Inferences
- A Rust runtime can parse Comfy repacks: read the `*.comfy_quant` uint8 tensor as JSON, dispatch on the format name, and dequantize `float8_e4m3fn` weights as `w.to(f32) * weight_scale` (per-tensor). NVFP4 needs the exact `TensorCoreNVFP4Layout` packing (block scale dtype, swizzle), which is defined only in comfy-kitchen's code, so that path needs reading its kernels or re-quantizing from bf16 oneself.
- Older "fp8_scaled" repacks (e.g. the Aug-2025 `qwen_2.5_vl_7b_fp8_scaled.safetensors`) predate `comfy_quant`; their on-disk convention was not confirmed from current source (see Gaps).

### Gaps
- Official `docs.comfy.org/advanced/quantization` was 404; the `_quantization_metadata` description is from a mirror.
- The pre-`comfy_quant` "scaled_fp8" convention (a marker tensor plus per-weight `scale_weight`) is my recollection of older ComfyUI and was not found in current `ops.py`; verify by inspecting the local `qwen_2.5_vl_7b_fp8_scaled.safetensors` header.
- No source states whether comfy-kitchen's NVFP4 packing equals NVIDIA ModelOpt's; treat as incompatible until tested.
- Whether the `nunchaku-tech` namespace has an official Edit-2511 release was not confirmed (search index did not surface the org page).
